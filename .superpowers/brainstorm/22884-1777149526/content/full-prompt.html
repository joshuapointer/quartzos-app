## Context You are a UX designer tasked with redesigning the QuartzOS mobile app. QuartzOS is a companion app for the Dab Rite PRO v2.2 — a Bluetooth IR thermometer used to monitor temperatures during cannabis concentrate (dabbing) sessions. The app connects to the physical device via Bluetooth Low Energy and provides: - Real-time temperature monitoring - Device configuration (alarms, colors, sounds) - Preset management (saved configurations) - Session history and temperature waveform logging Platform: iOS and Android native mobile app Primary users: Cannabis concentrate enthusiasts who want precise temperature control for optimal sessions. They use this app in low-light conditions, often one-handed, during an active ritual. The app should feel premium and purposeful. Creative direction: Full creative freedom. You are not constrained by the current design. --- ## Current Screens 1. Home Screen (primary screen) The core real-time experience. Shows a large animated temperature display, connection status (OFFLINE / CONNECTING / LIVE + signal strength), dab and dunk alarm thresholds, a session timer, and peak temperature during an active session. Quick-access to Settings and device scanning. Pain point: Cluttered — the temperature display needs to breathe. Supporting info crowds the hero element. 2. Settings Screen Device configuration: temperature unit (°F/°C), dab/dunk alarm thresholds, 4 RGB color theme slots for the physical device's screen, alert toggles (sound, light, night mode, LED guide), volume, and sound effect selection. Pain point: Unclear distinction from Presets — users don't know whether to change settings here or use a preset. 3. Presets Screen A list of saved device configurations. Includes 4 built-in presets and unlimited custom ones. Each preset shows a color swatch. Users can create, edit, delete, and apply presets — applying pushes all settings to the device at once. Pain point: Overlaps confusingly with Settings. The distinction between "current settings" and "saved named presets" isn't visually clear. 4. History Screen A log of all past sessions. Each entry shows timestamp, duration, a sparkline temperature graph (30-point waveform), alarm crossing markers, peak temperature reached, and an optional notes field. Sessions can be shared. --- ## Pain Points to Address 1. Cluttered Home screen — The temperature display is the hero. Everything else should step back until needed. 2. Disconnected navigation — Tab-based nav doesn't reinforce that this app is about one real-time task. The UX should feel focused and purposeful, not like a generic settings app. 3. Settings/Presets confusion — The redesign should make it immediately obvious that Presets are named snapshots of Settings — and clarify when to use each. 4. Design quality — The app is used for a ritualistic, sensory experience. It deserves a premium, intentional visual design that matches that energy. --- ## Phase 1 — Explore Design Directions Propose 2–3 distinct design directions for the full app. For each direction: - Give it a name and a one-sentence vibe description - Build a self-contained HTML mood-board showing: - Color palette (5–7 swatches with hex values) - Typography pairing (heading + body font) - 2–3 sample UI components in that style (e.g., temperature readout, button, list item) - A short rationale (2–3 sentences) explaining why this direction suits the app and its users Present all directions in a single directions.html file with a side-by-side or stacked comparison layout so they can be evaluated together. Wait for the user to select a direction (or ask to blend elements) before proceeding to Phase 2. --- ## Phase 2 — Full Screen Mockups Once a direction is chosen, build full HTML/CSS mockups for all 4 screens plus a navigation hub: - home.html — Home screen - settings.html — Settings screen - presets.html — Presets screen - history.html — History screen - index.html — Hub page linking all 4 screens with a one-line description of each Requirements for every mockup: - Mobile viewport: 390px wide × 844px tall (iPhone 14 proportions) - Include <meta name="viewport" content="width=device-width, initial-scale=1"> - Self-contained: all CSS and JS inline, zero external dependencies - Realistic content: use actual temperature values (e.g., 545°F, 380°F), real-sounding preset names (e.g., "Low Temp Terp", "Flavor Chaser", "Banger Hanger"), real session timestamps - Show at least one active/interactive state per screen where it adds clarity (e.g., active session on Home, an applied preset on Presets) - Each mockup should visibly address the pain point listed for that screen --- Ask any clarifying questions before starting Phase 1.
