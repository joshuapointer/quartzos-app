Wireframe Agent Prompt — Structure Overview

Approach 3: Direction-First. Review each section and let me know if anything needs adjusting.

Section 1 — App Context

What the app is, who uses it, and the platform (iOS/Android mobile). Sets up the agent with enough background to make informed design decisions without overwhelming detail.

Section 2 — Current Screens Inventory

A concise description of the 4 main screens (Home, Settings, Presets, History) and key modals (Scan, Color Picker). Includes what each screen does and the current design aesthetic (Frutiger Aero / skeuomorphic).

Section 3 — Pain Points to Address

The four specific problems: cluttered Home screen, disconnected navigation, Settings/Presets overlap confusion, and the general need for a high-quality design refresh. These are design constraints, not prescriptions.

Section 4 — Phase 1 Instructions (Direction Exploration)

The agent's first task: propose 2–3 distinct design directions for the whole app. Each direction gets a brief HTML mood-board — color palette, typography feel, sample component treatment. The agent should name and briefly describe each direction before showing it.

Section 5 — Phase 2 Instructions (Full Mockups)

After the user picks a direction, the agent builds full-fidelity HTML/CSS mockups for all 4 screens. Each mockup uses a mobile viewport (390px wide), includes realistic content (no lorem ipsum), and shows both idle and active states where relevant.

Section 6 — Output Requirements

Technical constraints: self-contained HTML files, mobile viewport meta tag, no external dependencies (inline CSS/JS only), one file per screen, a single index.html linking all screens for easy navigation.
